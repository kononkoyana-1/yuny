# Подключение Gemini — с нуля

Инструкция для состояния «нет ничего»: ни ключа, ни проекта в Google, ни
настроенных секретов. В конце — работающая генерация в Edge Functions.

Занимает 15–20 минут, из них 10 — ожидание деплоя.

> **Что уже сделано в коде.** Шлюз `aiJson()` в
> `supabase/functions/_shared/shared.ts` переписан на Gemini, все восемь мест,
> где проект обращается к AI, идут через него. Менять код не нужно — нужно
> выдать ключ, положить его в секреты и передеплоить функции.

---

## 0. Развилка, на которой легко потерять час

У Google **два разных способа** обращаться к Gemini, и они несовместимы:

| | Google AI Studio | Vertex AI |
| --- | --- | --- |
| Где | `aistudio.google.com` | Google Cloud Console |
| Авторизация | **API-ключ** — строка | Service account, OAuth-токены |
| Эндпоинт | `generativelanguage.googleapis.com` | `*-aiplatform.googleapis.com` |
| Бесплатный уровень | Есть | Нет |

**Нам нужен первый.** Код ходит на `generativelanguage.googleapis.com` и
передаёт ключ заголовком `x-goog-api-key`. Если начать с Google Cloud Console
и «Vertex AI», вы получите сервисный аккаунт и JSON-файл, которые сюда не
подойдут.

Слово «Google AI Platform» исторически означало Vertex. Идти надо в **AI
Studio**.

---

## 1. Выписать ключ

1. Открыть <https://aistudio.google.com/api-keys>.
2. Войти под своим Google-аккаунтом. Отдельной регистрации нет.
3. Принять условия Gemini API, если спросит.
4. Нажать **Create API key**.
5. Google предложит выбрать или создать Cloud-проект. Если проектов нет —
   создать новый; ключ должен где-то жить, но заниматься этим проектом дальше
   не придётся.
6. Скопировать ключ. Он показывается **один раз** — потом только удалить и
   выпустить новый.

Формат ключа зависит от того, когда он выдан. Старые «traffic keys» выглядят
как `AIzaSy…` (около 39 символов); все новые ключи AI Studio выпускаются как
**auth keys** и начинаются с `AQ.` — они длиннее и выглядят иначе. Оба рабочие,
проверять формат глазами не надо: это делает `gemini-check.mjs`.

### Если кнопка Create API key недоступна

Значит, аккаунт входит в организацию Google Workspace, где нет прав. Нужны
разрешения `apikeys.keys.create`, `serviceusage.services.enable`,
`resourcemanager.projects.get` — их даёт роль Project Editor. Альтернатива без
администратора: создать личный Cloud-проект вне организации и выпустить ключ
в нём.

### Куда его пока положить

**Никуда в репозиторий.** Ни в `.env`, ни в файл, ни в коммит. До шага 4 он
живёт в буфере обмена или в менеджере паролей. Ключ, попавший в git, считается
скомпрометированным даже после удаления коммита.

## 2. Проверить ключ до того, как он попадёт в прод

```bash
GEMINI_API_KEY=<ваш ключ> node scripts/gemini-check.mjs
```

Скрипт не требует установки — ни зависимостей, ни сборки.

Он делает три вещи:

1. подтверждает, что ключ вообще работает;
2. перечисляет модели, до которых **этот** ключ реально достаёт — id на
   странице с ценами и id, который принимает API, совпадают не всегда;
3. делает настоящий вызов со `responseSchema` и проверяет, что модель вернула
   JSON по схеме. Это основа всего: `aiJson()` возвращает структуру, а не
   текст, который пришлось бы разбирать.

Успешный вывод заканчивается так:

```
✓ gemini-3.5-flash honours responseSchema. Set it as GEMINI_MODEL:
    supabase secrets set GEMINI_API_KEY=… GEMINI_MODEL=gemini-3.5-flash
```

Проверить конкретную модель:

```bash
GEMINI_API_KEY=<ваш ключ> node scripts/gemini-check.mjs gemini-3.5-flash
```

## 3. Выбрать модель

Проверено на странице моделей 2026-08-29: **`gemini-3.5-flash` существует и
помечен как stable**. Это и есть рабочий выбор — берите его.

Действующие flash-модели:

| id | Статус | Комментарий |
| --- | --- | --- |
| `gemini-3.5-flash` | Stable | **Рекомендуется.** |
| `gemini-3-flash-preview` | Preview | Preview может исчезнуть без замены. |
| `gemini-3.1-flash-lite` | Stable | Дешевле и слабее; для ранжирования тем хватит, для генерации миссий — вряд ли. |
| `gemini-2.5-flash` | Stable | Прошлое поколение. |

Дефолт в коде — `gemini-3.5-flash`, то есть без `GEMINI_MODEL` получится
ровно он. Секрет всё равно поставьте: пусть выбор модели будет виден в
настройках, а не только в исходнике.

**Алиаса `gemini-flash-latest` здесь сознательно нет.** Он никогда не отдаёт
404, и это звучит безопаснее, чем есть: алиас переезжает на новый релиз по
расписанию Google, а выход этого генератора идёт прямиком в учебный материал.
Исчезнувшая модель падает громко на следующем же вызове; модель, которая тихо
стала другой моделью, даёт слегка другой контент, и этого здесь никто не
заметит.

Цены и лимиты бесплатного уровня: <https://ai.google.dev/gemini-api/docs/pricing>
и <https://ai.google.dev/gemini-api/docs/rate-limits>. Точные цифры я не
переношу сюда специально — они меняются, а устаревшая цифра в документе хуже
ссылки. Бесплатного уровня для разработки и прогонов онбординга хватает;
переход на платный — кнопка **Upgrade** на той же странице ключей.

Одно следствие бесплатного уровня, о котором стоит знать заранее: на нём
**ваши запросы используются для улучшения продуктов Google**. На платном —
нет. Для учебного контента из открытых источников это, скорее всего,
неважно, но решение ваше.

## 4. Положить секреты в Supabase

Два секрета: `GEMINI_API_KEY` и `GEMINI_MODEL`.

Прямая ссылка на ваш проект:

<https://supabase.com/dashboard/project/ixtfifglohppaimvyvui/settings/functions>

Если ссылка не открылась — Dashboard → ваш проект → **Edge Functions** →
**Secrets** (в некоторых версиях панели: Project Settings → Edge Functions).

Добавить две записи:

```
GEMINI_API_KEY = <ваш ключ>
GEMINI_MODEL   = gemini-3.5-flash
```

Секреты доступны функциям сразу, без передеплоя. **Но** код функций сейчас
старый — поэтому шаг 5.

> Через MCP секреты выставить нельзя: у сервера Supabase нет такого
> инструмента. Только панель или CLI (`supabase secrets set`), а CLI здесь не
> установлен.

## 5. Передеплоить функции — все десять

Ключевой момент: изменился `_shared/shared.ts`, а его импортируют **все**
функции. В Supabase общий модуль не деплоится отдельно — он вкомпилируется в
каждую функцию при сборке. Значит, обновить надо все:

```
activity-submit      assessment-complete   assessment-next
content-import       goal-analyze          goal-confirm
goal-set-time        material-ingest       mission-generate
recommendation-get
```

Передеплой только тех, что менялись по смыслу, оставит остальные восемь
вызывать Anthropic — и они будут падать, потому что ключа Anthropic нет.

Скажите слово — задеплою все десять через MCP за один заход. Сам не делаю:
это запись в ваш живой проект.

Вручную (нужен Supabase CLI и personal access token):

```bash
supabase functions deploy --project-ref ixtfifglohppaimvyvui
```

### Заодно: лишняя задеплоенная функция

В проекте развёрнута `mission-from-content`, которой **больше нет в коде** —
её удалили, когда логика переехала в `mission-generate`. Она осталась висеть
как ACTIVE. Не мешает, но это мёртвая точка входа с доступом к service role.
Удалить стоит; скажете — уберу.

## 6. Проверить, что заработало

Порядок от дешёвого к дорогому.

**6.1. Онбординг целиком** — единственная настоящая проверка. Пройти
приложение: цель → анализ → тест → результат → стратегия. Смотреть на два
места:

- **Экран 04** — заголовок цели, ситуации и темы должны быть про то, что вы
  написали. Если там общие фразы про «everyday conversations» — работает
  детерминированная ветка, ключ не подхватился.
- **Экран 08** — список модулей с человеческим объяснением у каждого. Если
  вместо модулей нумерованный список фокус-областей — карта не построилась.

**6.2. Логи функций** при сомнениях:

<https://supabase.com/dashboard/project/ixtfifglohppaimvyvui/logs/edge-functions>

Что искать:

| Запись | Значение |
| --- | --- |
| `ai_http_error … 400` | Схема не понравилась Gemini. Наш баг, детали в той же строке. |
| `ai_http_error … 401/403` | Ключ неверный или API не включён в проекте. |
| `ai_http_error … 429` | Упёрлись в лимит. Одна повторная попытка уже сделана. |
| `ai_finish_reason … MAX_TOKENS` | Ответ обрезан. Поднять `maxTokens` у конкретного вызова. |
| `ai_blocked` | Фильтры безопасности. Смотреть на входной текст. |
| `roadmap_build_failed` | Карта не собралась; вердикт теста при этом сохранён. |

**6.3. Событие `roadmap_built`** — сколько модулей реально получилось:

```sql
select payload->>'modules' as modules,
       payload->>'assessed_cefr' as assessed,
       payload->>'required_cefr' as required,
       created_at
from public.events
where name = 'roadmap_built'
order by created_at desc limit 10;
```

`modules = 0` — не ошибка ключа. Это значит, что у тем нет проверенного
контента на полосах между измеренным и требуемым уровнем. На сегодня
проверенный контент есть только на A1–A2.

## 7. Чего ожидать, а чего нет

**Что заработает сразу:** осмысленный разбор цели, `required_cefr`, темы под
цель, ранжирование модулей дорожной карты, объяснения «почему этот модуль»,
итог теста, обратная связь на задания, разбор загруженных материалов.

**Что не изменится:** задания с вариантами ответа и на подстановку слова
по-прежнему проверяются по `activity_answer_keys` без всякого AI. Ключ на это
не влияет — и не должен.

**Что останется узким местом:** контентный путь миссий. В базе 206
сгенерированных упражнений, из них проверенных — **ноль**, поэтому
`missionFromContent` не отдаёт ничего и всё уходит в авторскую генерацию.
Ключ Gemini этого не чинит; чинит ретро-проверка контента (этап 1b).

## 8. Если что-то пошло не так

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Онбординг проходится, но тексты шаблонные | `GEMINI_API_KEY` не виден функции | Секрет добавлен? Функции передеплоены после добавления? |
| `error_code: ai_unavailable` | Ключ неверный, лимит, или Gemini недоступен | `node scripts/gemini-check.mjs` с тем же ключом |
| `error_code: ai_invalid_response` | 400 от Gemini или обрезанный ответ | Логи функций, строка `ai_http_error`/`ai_finish_reason` |
| `gemini-check.mjs` говорит 404 на модель | Такого id у этого ключа нет | Запустить без аргумента — он перечислит доступные |
| Экран 04 падает с ошибкой разбора | Функции старой версии | `goal-analyze` не передеплоен |
| Карта пустая при рабочем ключе | Нет проверенного контента на нужных полосах | Ожидаемо; смотреть `roadmap_built` |

### Как всё выключить

Удалить `GEMINI_API_KEY` из секретов. Каждый генератор имеет
детерминированную ветку — онбординг, тест, миссия, задание, обратная связь
проходятся полностью без ключа. Это не заглушки: ветка держит приложение
работоспособным, просто тексты становятся общими. Передеплой не нужен.

### Если ключ утёк

1. <https://aistudio.google.com/api-keys> → удалить ключ. Он перестаёт
   работать сразу.
2. Выпустить новый, обновить секрет в Supabase.
3. Проверить биллинг в Cloud Console на предмет чужого расхода.

### Findings

- **blocker B1** · `apps/mobile/shared/ui/Sheet.tsx:77` (срабатывает из `apps/mobile/features/dictionary/MyDictionary.tsx:88` и `apps/mobile/app/folder/[id].tsx:400,408`) · §17 accessibility, работа в web · **владелец корня `design-system-agent`, вызовы — `frontend-builder`.**
  Ожидалось: закрытый лист не трогает фокус. Фокус возвращается только тогда, когда лист действительно закрыли.
  Получено: эффект `Sheet` вызывает `returnFocusTo(returnFocusRef)` в ветке `visible === false` и на первом монтировании тоже. На Главной это не проявлялось, потому что ref ставится только после открытия. Новые вызовы передают живой ref кнопки уже при монтировании. Последствия, все проверены в отрисовке:
  1. **Стёр запрос — не можешь печатать.** Пользователь набирает `hao` и стирает его Backspace'ом. Через 300 мс монтируется `MyDictionary`, фокус уходит из поля на «Новая папка», и следующие буквы `da` в поле не попадают: значение остаётся пустым (`16-erase-then-type-light-390x844.png`). Это ломает главное действие экрана.
  2. При открытии вкладки «Словарь» фокус с видимой обводкой стоит на «Новая папка» (`01-mine-light-390x844.png`, чёрная рамка).
  3. При открытии папки фокус проходит через «Переименовать» и остаётся на «Удалить папку»: первое, что услышит диктор и на что сработает Enter, — разрушительное действие (трасса `focusin` в r1c, `15-folder-open-focus-light-390x844.png`).
  Нужно: `Sheet` не должен возвращать фокус, если до этого не был открыт. Как именно — решает владелец примитива. До этого вызывающий код может передавать ref только после открытия, как уже сделано в `dictionary.tsx:190`. Проверять надо в отрисовке по всем трём сценариям выше.

- **blocker B2** · `apps/mobile/app/(tabs)/dictionary.tsx:168` · §17 accessibility-атрибуты · владелец `frontend-builder`.
  Ожидалось: поле поиска в дереве доступности — редактируемое поле (`searchbox`) с именем «Поиск по словарю».
  Получено: `accessibilityRole="search"` в react-native-web превращается в `role="search"` на самом `<input>`. Это роль ориентира (landmark), и она перекрывает роль поля. В дереве Chromium: `search "Поиск по словарю"`, `getByRole("searchbox")` = 0, `getByRole("textbox")` = 0. Главное поле экрана диктор объявляет как область страницы, а не как поле ввода. `inputMode="search"` уже даёт `type="search"`, то есть `searchbox`.
  Нужно: убрать роль с поля. Если нужен ориентир, повесить его на обёртку, а не на `<input>`.

- **blocker B3** · `apps/mobile/features/dictionary/ArticleSheet.tsx:165-167,170-188,215` · «Универсальные правила экрана» (empty), §11/04 «Кнопка „в мой словарь“ с выбором папки» · владелец `frontend-builder`, текст — через пользователя (см. Open Question 1).
  Ожидалось: у нового пользователя папок ноль, и через этот путь проходит каждое первое сохранение. Выбор папок с пустым списком должен явно вести к созданию папки.
  Получено (`19-picker-nofolders-{light,dark}-390x844.png`): заголовок «В какие папки положить „打“», подсказка «Слово может лежать в нескольких папках сразу» (`ru.ts:189`) — про папки, которых нет. Под ней пустой блок списка даёт двойной отступ, потом безымянное поле с плейсхолдером «Новая папка». Единственная заметная кнопка — primary «Готово». Она молча возвращает к статье, ничего не сохранив, и там снова «В мой словарь». Пустое состояние у этого места не спроектировано, и primary ведёт в тупик.
  Нужно: отдельный вид для ноля папок — поле названия как главный шаг и одно действие, которое создаёт папку и кладёт в неё слово. «Готово» как primary не должно стоять раньше, чем слово куда-то положено. Строки взять из ответа на Open Question 1.

### Open Questions

1. **К пользователю (для B3).** Какие строки нужны у выбора папок, когда папок ещё нет: заголовок, подсказка и подпись кнопки, которая создаёт первую папку и кладёт в неё слово? Нужна ли папка по умолчанию, которую сервер создаёт сам (например, «Все слова»)? Это продуктовое решение, ТЗ §11 его не фиксирует. Если папка по умолчанию будет, B3 решается на backend, а не версткой.
2. **К пользователю.** Одно слово в выдаче показано дважды: в «В моём словаре» и в «Словарь БКРС» с пометкой «В моём словаре» (`02-search-hanzi-light-390x844.png`). Это осознанно, или сохранённые слова надо убирать из выдачи БКРС?
3. Когда поиск БКРС падает, `ErrorState` (`dictionary.tsx:70-80`) закрывает собой и совпадения из своего словаря, хотя они лежат на клиенте и доступны. Заголовок ошибки «Не получилось найти слово» (`ru.ts:171`) читается почти как пустой ответ. Не дефект по ТЗ, наблюдение для спеки.
4. В статье уже сохранённого слова primary нет, «Изменить папки» — secondary (`ArticleSheet.tsx:89-90`). Я считаю это верным понижением, но в спеке это должно быть записано явно.
5. На 1280 строки выдачи и папки растянуты на 1232 px (`02-search-hanzi-light-1280x844.png`, `10-folder-light-1280x844.png`). Ширины содержимого для широкого web в токенах нет (`breakpoints` есть только у `Sheet`). Вопрос к `design-system-agent`, раз web теперь единственный target.

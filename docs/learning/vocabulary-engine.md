# Движок изучения лексики: от «видел» к «вспоминаю и использую»

Статус: черновик для обсуждения · 2026-09-23 · ветка `feature/vocab-learning-engine`

Документ отвечает на 12 вопросов постановки. Идеи постановки не принимаются по
умолчанию: где механика педагогически слабая, создаёт ложный прогресс или
стоит дороже, чем даёт, — это сказано прямо (помечено **⚠ Критика**).

Исходные ограничения:

- нет аудио и speaking — работаем с иероглифами, пиньинем, переводом,
  контекстом и письменным воспроизведением;
- слова приносит сам пользователь: вручную, из поиска БКРС, из файла
  (`words-extract`), и раскладывает по папкам;
- уже есть: `dictionary_entries` (БКРС, ~915 тыс. статей, `compact` — короткие
  значения, `hsk_level`), `hsk_words`, `user_dictionary_folders/items`,
  Gemini через `aiJson`, Edge Functions.

---

## 0. Главные решения — одним списком

1. **Обучается лексема, а не строка в папке.** Одно слово может лежать в трёх
   папках (сейчас это три строки `user_dictionary_items`). Состояние памяти —
   одно на `(user, headword, reading, смысл)`. Папки — это вход и контекст, но
   не единица обучения.
2. **Состояние слова — не лестница, а вектор из 4 навыков** (ЧИТАЮ, ПИНЬИНЬ,
   ПИШУ, ИСПОЛЬЗУЮ), у каждого своя память (стабильность, сложность). Стадия
   «Знакомо → … → Устойчиво» выводится из вектора только для интерфейса.
3. **Recognition и recall — это не разные навыки, а разная сила одного
   упражнения.** Выбор из вариантов и свободное вспоминание тренируют одну
   связь, но с разным весом как доказательство. Хранить их отдельными
   процентами — двойной учёт и ложная точность.
4. **SRS — FSRS на каждый навык** (готовая открытая модель, библиотека
   `ts-fsrs`, MIT), а собственная ценность — в слое над ней: оценку ставит не
   пользователь, а классификатор ответа (тип ошибки, скорость, формат).
5. **Пара путаемых слов — отдельный объект с собственным расписанием.** Пока
   пара не различается стабильно, интервалы обоих слов ограничены сверху
   интервалом пары.
6. **Контекст генерирует ИИ, а проверяет код**: каждое предложение режется на
   слова по словарю, и все слова кроме целевого должны быть в известном
   пользователю наборе. Модели это говорится в промпте, но держит правило код
   (тот же принцип, что уже работает в `wordsExtract.ts`).
7. **Нагрузка — ограничение первого класса.** 4 навыка × слово умножают число
   повторений. Приём новых слов в день рассчитывается от прогноза завтрашней
   нагрузки, а не задаётся константой. Иначе через три недели пользователь
   тонет в долгах и уходит — самая частая смерть SRS.
8. **Папка не запускает «урок по папке».** Ежедневная сессия — общая,
   перемешанная. Папка даёт порядок приёма новых слов, тему для сцен и
   фокус-режим.

## 1. Learning model — модель состояния слова

### Почему не `Unknown → Recognition → Recall → Context → Mastery`

**⚠ Критика линейной лестницы.**

- **Навыки китайского слова расходятся, а не идут друг за другом.** Типичный
  ученик читает 1500 знаков, а пишет по памяти 300. Слово может быть на
  «Context» по чтению и на «Unknown» по написанию. Одна ступенька на слово
  прячет это.
- **Лестница монотонна, память — нет.** Слово, которое было на «Context»,
  через три месяца может не узнаваться. Лестница либо врёт (показывает
  старую ступеньку), либо откатывает целиком (обесценивает прошлый труд).
- **Для китайского связь «форма → звук» непрозрачна.** В русском или
  английском по написанию почти всегда можно прочесть слово. В китайском
  знание значения 买 не даёт ни mǎi, ни тона. Поэтому звук (пиньинь) — это
  отдельный канал памяти, а не следствие распознавания.

### Предлагаемая модель

Слово = **4 следа памяти** (навыка, см. раздел 2) + **производная стадия**
для интерфейса + флаги.

```
               ┌─ ЧИТАЮ     (买 → «покупать»)        S, D, last, due
лексема 买 mǎi ├─ ПИНЬИНЬ   (买 → mǎi)               S, D, last, due
               ├─ ПИШУ      («покупать» → 买)        S, D, last, due   [можно выключить]
               └─ ИСПОЛЬЗУЮ (我想__咖啡 / RU→ZH)      S, D, last, due, contexts_passed
флаги: new · confusion(卖) · leech · goal=read_only
```

S — стабильность в днях (через S дней вероятность вспомнить падает до 90%),
D — сложность 1–10 (раздел 4).

**Разблокировка навыков** — не все сразу (это и педагогика, и контроль
нагрузки):

| Навык | Открывается, когда | Почему |
|---|---|---|
| ЧИТАЮ | сразу после знакомства | базовая связь форма → значение |
| ПИНЬИНЬ | сразу после знакомства | звук кодируется отдельно; тон нужно ловить с первого дня, пока ошибка не закрепилась |
| ПИШУ | S(ЧИТАЮ) ≥ 3 дня | производство до устойчивого узнавания — перебор; выбор формы из похожих путает только что увиденное |
| ИСПОЛЬЗУЮ | S(ЧИТАЮ) ≥ 3 и S(ПИНЬИНЬ) ≥ 2 | в предложении слово должно узнаваться без усилия, иначе задача — расшифровка, а не использование |

**Производная стадия** (что видит пользователь):

| Стадия | Условие | Смысл для человека |
|---|---|---|
| Новое | ещё не показано | — |
| Знакомлюсь | показано, S(ЧИТАЮ) < 3 | «видел» |
| Узнаю | S(ЧИТАЮ) ≥ 3 | «понимаю, когда вижу» |
| Вспоминаю | S(ПИНЬИНЬ) ≥ 7 и (S(ПИШУ) ≥ 7 или ПИШУ выключен) | «могу вспомнить сам» |
| Использую | ИСПОЛЬЗУЮ пройден в ≥ 2 разных предложениях, последнее — ≥ 7 дней после первого | «могу употребить» |
| Устойчиво | S(ЧИТАЮ) ≥ 60, S(ПИНЬИНЬ) ≥ 30, S(ПИШУ) ≥ 30, S(ИСПОЛЬЗУЮ) ≥ 21, нет активной путаницы | «помню через месяцы» |

Стадия **может понизиться**: считается по текущей вероятности вспомнить, а не
по максимуму за историю. Это честно. Чтобы не было драмы, понижение
показывается как «пора освежить», а не как «потеряно».

**Флаги:**

- `confusion` — есть активная пара путаницы (раздел 5);
- `leech` — ≥ 4 провала одного навыка: слово перестают гонять тем же способом
  (раздел 5);
- `goal = read_only` — пользователь (или правило папки) сказал «писать не
  нужно». Навык ПИШУ не открывается, «Вспоминаю» считается без него.

**⚠ Критика «Mastery».** Постоянного «выучено навсегда» нет. «Устойчиво»
означает, что слово держится на интервалах в месяцы. Повторения продолжаются,
просто редко (раз в 2–6 месяцев) и почти бесплатно по времени.

## 2. Skill model — какие навыки отслеживать

Разбор кандидатов из постановки:

| Навык из постановки | Решение | Почему |
|---|---|---|
| meaning recognition (买 → выбрать значение) | **= ЧИТАЮ**, лёгкий формат | тот же след, что и meaning recall, только слабее как доказательство |
| meaning recall (买 → вспомнить значение) | **= ЧИТАЮ**, трудный формат | см. выше |
| hanzi recognition | **= ЧИТАЮ** | узнать форму — и есть «читаю» |
| hanzi production («покупать» → 买) | **ПИШУ** | отдельный и самый дорогой навык |
| pinyin recognition (买 → выбрать mǎi) | **= ПИНЬИНЬ**, лёгкий формат | — |
| pinyin production (买 → набрать mǎi) | **ПИНЬИНЬ** | звук + тон; без аудио это единственный канал звука |
| pinyin → hanzi (mǎi → 买) | **не отдельный навык в MVP** | много омофонов (shì — десятки знаков), задача неоднозначна без значения. Как навык ввода покрывается ПИШУ в формате «как в IME» (ниже) |
| meaning → pinyin («покупать» → mǎi) | **не отдельный** | почти полностью = ПИШУ + ПИНЬИНЬ; без аудио пользы мало |
| contextual usage | **ИСПОЛЬЗУЮ** | единственный навык, где проверяется сочетаемость и порядок слов |

### MVP: 4 навыка

1. **ЧИТАЮ** — форма → значение.
2. **ПИНЬИНЬ** — форма → звук с тоном. Внутри ошибки делятся на слог и тон
   (раздел 5), но след один.
3. **ПИШУ** — значение → форма. Что именно значит «написать», решается
   осознанно:
   - **В MVP «написать» = выбрать правильный знак среди похожих и омофонов.**
     Так человек пишет в реальной жизни: набирает mǎi в IME и выбирает 买, а
     не 卖/麦/马. Навык реальный, проверяется автоматически и прямо бьёт по
     путанице 买/卖.
   - **Рукописное воспроизведение** — SHOULD: квиз по чертам (`hanzi-writer`,
     MIT, данные Make Me a Hanzi). Проверка идёт против известного целевого
     знака, так что распознаватель почерка не нужен. Для тех, кому важно
     писать рукой (экзамен, школа).
   - Самооценка «напишите на бумаге и сравните» — запасной формат, вес
     низкий.
4. **ИСПОЛЬЗУЮ** — слово в предложении: пропуск, сборка, перевод.

**⚠ Критика.** 7 отдельных процентов на слово из постановки — это ложная
точность. Данных на слово — десятки ответов, «hanzi recall 60%» при 5 ответах
— шум. Внутри хранится вероятность (R) и стабильность (S). Пользователю
показываются 4 сегмента с 3–4 градациями, а не проценты.

### LATER

- **Уровень знака, а не слова**: 买 внутри 买东西, 购买, 买单. Перенос знания
  знака на новые слова — сильная вещь для китайского, но это граф знаков и
  отдельная модель переноса. Сначала — уровень слова и данные.
- **Тон как отдельный след.** Если тоновые ошибки окажутся массовыми.

## 3. Exercise engine — выбор следующего упражнения

### Каталог упражнений

У каждого упражнения есть: навык (какой след обновляется), формат, **вес
доказательства** `m_format` (насколько успех говорит о памяти), способ
проверки.

| Код | Упражнение | Навык | m_format | Проверка |
|---|---|---|---|---|
| R1 | 买 → выбрать значение из 4 | ЧИТАЮ | 0.5 | авто |
| R2 | 买 → вспомнить значение, открыть, «помнил / не помнил» | ЧИТАЮ | 0.8 | самооценка |
| R3 | 买 в коротком предложении → выбрать перевод предложения | ЧИТАЮ (+ИСПОЛЬЗУЮ 0.3) | 0.9 | авто |
| P1 | 买 → выбрать пиньинь из 4 (mǎi / mài / mā / mǎ) | ПИНЬИНЬ | 0.5 | авто |
| P2 | 买 → набрать пиньинь (`mai3` / `mǎi`) | ПИНЬИНЬ | 1.0 | авто, нормализация |
| W1 | «покупать · mǎi» → выбрать знак из 6 похожих/омофонов | ПИШУ | 0.7 | авто |
| W2 | «покупать» (без пиньиня) → выбрать знак из 6 | ПИШУ | 0.85 | авто |
| W3 | «покупать» → нарисовать по чертам (hanzi-writer) | ПИШУ | 1.2 | авто |
| C1 | 我想 ___ 咖啡。(+перевод) → выбрать из 4 слов пользователя | ИСПОЛЬЗУЮ | 0.6 | авто |
| C2 | «Я хочу купить кофе» → собрать 我想买咖啡 из плиток | ИСПОЛЬЗУЮ (+ПИШУ 0.3) | 1.0 | авто, допустимые порядки от генератора |
| C3 | 我想 ___ 咖啡。→ набрать пиньинем пропуск | ИСПОЛЬЗУЮ (+ПИНЬИНЬ 0.5) | 1.1 | авто |
| C4 | «Я хочу купить кофе» → написать по-китайски целиком | ИСПОЛЬЗУЮ | 1.3 | ИИ-оценка (SHOULD) |
| X* | упражнения на пару путаницы (раздел 5) | пара | 0.7–1.2 | авто |

**⚠ Критика предложенных типов.**

- **Matching** (соединить 5 знаков с 5 значениями) — слабое упражнение:
  последние пары решаются исключением, последняя достаётся бесплатно. Годится
  как разминка, но **не обновляет память** (вес 0), иначе рисует ложный
  прогресс.
- **Character construction** (собрать знак из данных компонентов) — по сути
  узнавание с подсказкой: компоненты уже на экране, половина ответа выдана.
  Разбор на компоненты полезен как **объяснение** при ошибке (раздел 6), а
  упражнение — LATER или никогда.
- **C1 (пропуск с выбором)** — это узнавание в контексте, не использование.
  Засчитывать его как «умеет употреблять» нельзя, отсюда низкий вес.
  «Использую» требует C2–C4.
- **Качество дистракторов решает всё.** Выбор 买 из {买, 桌子, 猫, 红} — не
  проверка. Дистракторы берутся так:
  1. из пар путаницы пользователя;
  2. из слов его словаря с общим знаком, тем же слогом или похожей формой;
  3. из словаря — омофоны и похожие по форме (данные компонентов — SHOULD);
  4. ИИ-список «часто путают с…», кэш на слово.

### Алгоритм сессии

Сессия — это ~10–15 минут, по умолчанию ≤ 60 упражнений; бюджет задаёт
пользователь.

```
build_session(user):
  1. Кандидаты-повторения:
       все (лексема, навык) открытые, где R(t) < 0.90 (просрочено),
       + активные пары путаницы, где R_pair < 0.90.
  2. Приоритет каждого кандидата:
       p = (0.90 − R)                    # насколько просрочено
         + 0.15 · lapses_recent          # недавно проваливал
         + 0.20 · (пара путаницы активна)
         + 0.10 · (папка в фокусе)
     Взять по убыванию p, пока хватает бюджета (оценка времени на формат).
  3. Новые слова: quota = intake_quota(user)  (ниже), порядок:
       папки в фокусе → недавно добавленные → меньший HSK;
       не брать в один день слово и его известную пару путаницы / антоним
       (см. «интерференция», раздел 8).
  4. Формат для каждого (лексема, навык) — по «желательной трудности»:
       подобрать самый трудный формат навыка, у которого ожидаемый успех
       ≥ 0.80 (ожидание = R с поправкой на формат, по логам пользователя);
       свежий навык (reps < 2) → лёгкий формат (R1, P1, W1, C1),
       S ≥ 7 → трудный (R2/R3, P2, W2/W3, C2/C3).
  5. Перемешивание (interleaving):
       - одно слово не встречается дважды подряд; между показами ≥ 3 других;
       - навыки чередуются; подряд не больше 2 одинаковых форматов;
       - новые слова: знакомство → через 2–4 других задания первое
         вспоминание (короткая задержка обязательна: сразу после показа
         ответ берётся из рабочей памяти и ничего не доказывает);
       - блок интервенции по паре идёт целиком (контраст нужен рядом).
  6. Во время сессии после каждого ответа:
       classify(answer) → (исход, тип ошибки, партнёр путаницы)
       → rating → обновить FSRS навыка(ов) (раздел 4)
       → обновить граф путаницы; при пороге — вставить интервенцию
       → провал: вернуть это же (лексема, навык) в конец сессии в лёгком
         формате (шаг переобучения), но в расписание идёт первая оценка.
```

**Приём новых слов** (самое важное для удержания пользователя):

```
intake_quota(user):
  due_tomorrow = прогноз числа упражнений на завтра (сумма по R(t+1) < 0.9)
  free = budget − due_tomorrow
  cost_new ≈ 6 упражнений в первую неделю на слово
  quota = clamp(floor(free / cost_new), 0, user_max_new (по умолч. 8))
```

Если долг большой — новых слов 0, и интерфейс говорит почему: «Сначала
освежим 40 слов, новые — завтра».

### Выход движка

На каждый шаг: `{ exercise_code, lexeme, skill, distractors, context_id?,
difficulty_tier }`. После ответа — новое `due` для каждого затронутого навыка
и пары.

## 4. SRS — адаптивная модель

### Основа: FSRS, а не SM-2 и не своя кривая

SM-2 (Anki по умолчанию) не знает вероятности вспомнить и одинаково растит
интервалы трудным и лёгким карточкам. FSRS — открытая модель памяти (кривая
забывания + стабильность + сложность), обученная на сотнях миллионов
повторений. Она уже лучше всего, что можно придумать с нуля. **Изобретать
кривую не нужно.** Преимущество строится на трёх вещах поверх неё:

1. оценку (Again/Hard/Good/Easy) выставляет классификатор ответа, а не
   пользователь;
2. один ответ обновляет несколько связанных следов (перенос между навыками);
3. путаница — отдельный объект, который ограничивает рост интервалов.

### Формулы (FSRS-подобно, веса стартовые, потом дообучаются на логах)

Вероятность вспомнить через t дней при стабильности S:

```
R(t, S) = (1 + F · t / S) ^ (−0.5),   F = 19/81 ≈ 0.2346      (R(S, S) = 0.90)
```

Первое упражнение навыка:

```
S0 = {Again: 0.4, Hard: 1.2, Good: 2.5, Easy: 6.0}[rating] × m_format   (для Again без множителя)
D0 = 5.0 + поправки слова: +1 знак ≥ 10 черт, +1 есть путаемое слово в словаре
     пользователя, +0.5 HSK ≥ 4 или вне HSK, −0.5 HSK 1, +0.5 многосложное слово для ПИШУ
```

Успех:

```
S' = S · (1 + G)
G  = 4.5 · (11 − D) · S^(−0.15) · (e^(1 − R) − 1) · m_rating · m_format
m_rating: Hard 0.5 · Good 1.0 · Easy 1.3
```

Смысл множителей:

- `(11 − D)` — трудные слова растут медленнее;
- `S^(−0.15)` — чем дольше помнишь, тем меньше относительный прирост;
- `e^(1−R) − 1` — **желательная трудность**: вспомнить почти забытое даёт
  больше, чем повторить свежее. Поэтому повторять «на всякий случай» раньше
  срока почти бесполезно, и движок этого не делает.

Ошибка — S не растёт, а падает, **по-разному в зависимости от типа ошибки**:

```
S' = max(0.4, S · k_err)
k_err: пусто / не знаю / неверно без связи   0.20   (настоящее забывание)
       путаница с конкретным словом          0.50   (слово помнит, не различает)
       тон неверный, слог верный             0.60   (частичное знание)
       верно, но только со второй попытки    0.70
D' = D + {Again 1.0, confusion 0.6, tone 0.5, Hard 0.3, Good −0.1, Easy −0.3}, D ∈ [1, 10]
```

### Как учитываются факторы из постановки

| Фактор | Где в модели |
|---|---|
| тип ошибки | `k_err` + маршрутизация (раздел 5); путаница бьёт не по слову, а создаёт пару |
| скорость ответа | правильный ответ быстрее 0.6 × медианы пользователя для этого формата → Easy, медленнее 2.5 × медианы → Hard. **Только двигает Good ↔ Easy/Hard, неправильный ответ никогда не спасает.** Медиана — своя на формат и устройство (набор на телефоне медленнее) |
| число успешных recall | уже внутри S (каждый успех умножает) |
| забывание | R(t), провалы → `lapses`, leech при ≥ 4 |
| сложность слова | D (стартовые поправки + обновления) |
| похожие слова | D0 +1; ограничение интервала парой путаницы: `due(навык) ≤ due(пара)`, пока S(пара) < 7 |
| контекст | успех в C2–C4 даёт «неявное повторение» ЧИТАЮ и ПИНЬИНЬ: Good × 0.3 (и не раньше чем через сутки после их последнего повторения — иначе двойной учёт) |

Цель удержания — 0.90 (стандарт FSRS). В настройках «Интенсивность»:
0.85 / 0.90 / 0.93. Выше 0.93 нагрузка растёт круто, а память почти нет.

**Дообучение весов** — LATER, после ~1000 ответов у пользователя или ~100
тыс. в сумме: оптимизатор FSRS на наших логах. Поэтому **лог каждого ответа
пишется сырым с первого дня** — это MUST, его не вернуть задним числом.

### Пример расчёта: 买 mǎi — покупать

У пользователя в словаре уже есть 卖 (из той же загрузки). D0 для ЧИТАЮ и
ПИНЬИНЬ = 5.0 − 0.5 (HSK 1) + 1 (卖 в словаре) = **5.5**; для ПИШУ ещё +1.5
за «первый показ формы, путаемой с известным» → **7.0**.

| День | Навык | Упражнение и ответ | До: S, t, R | Расчёт | После |
|---|---|---|---|---|---|
| 0 | — | Знакомство (не оценивается) | — | — | — |
| 0 | ЧИТАЮ | R1, верно, обычная скорость → Good | новый | S0 = 2.5 × 0.5 | **S = 1.25** |
| 0 | ПИНЬИНЬ | P2 `mai3`, верно → Good | новый | S0 = 2.5 × 1.0 | **S = 2.5** |
| 2 | ЧИТАЮ | R2, вспомнил, быстро → Easy | 1.25, t=2, R=0.853 | G = 4.5·5.5·0.967·0.159·1.3·0.8 = 3.95 | **S = 6.19**, D = 5.2 |
| 2 | ПИШУ | открыт (S(ЧИТАЮ) ≥ 3). W1: «покупать · mǎi» → выбрал **卖** | новый | Again, путаница 买→卖 #1 | **S = 0.4**, D = 7.6 |
| 3 | ПИНЬИНЬ | P2, набрал `mai4` | 2.5, t=3, R=0.883 | слог верен, тон нет → и это чтение 卖 → путаница #2 (k = 0.5) | **S = 1.25**, D = 6.1 |
| 3 | пара 买/卖 | порог 2 → **интервенция**: контраст + 4 задания, 4/4 | новая | Good, но сразу после объяснения → ×0.4: 2.5 × 0.4 | **S(пара) = 1.0**; ограничение: due(ПИШУ, ПИНЬИНЬ 买) ≤ due(пара) |
| 4 | пара | X2: 2 задания вперемешку, верно | 1.0, t=1, R=0.90 | G = 4.5·5·1·0.105·1·0.7 = 1.66 | **S = 2.66** |
| 4 | ПИШУ | W1, выбрал 买 → Good | 0.4, t=2, R=0.678 | G = 4.5·3.4·1.147·0.379·0.7 = 4.66 | **S = 2.26** (≤ пары, ограничение не срабатывает) |
| 5 | ПИНЬИНЬ | P2 `mai3` → Good | 1.25, t=2, R=0.853 | G = 4.5·4.9·0.967·0.159·1.0 = 3.39 | **S = 5.49**, но ограничено парой → due не позже дня 6 |
| 7 | пара | X3 в предложениях: 他在市场___水果 (卖), 我去超市___牛奶 (买) → верно | 2.66, t=3, R=0.889 | G = 4.5·5·0.864·0.117·1.2 = 2.73 | **S = 9.93** ≥ 7 → ограничение снято, пара «под наблюдением» |
| 8 | ИСПОЛЬЗУЮ | открыт. C1 我想 ___ 咖啡 → 买 | новый | S0 = 2.5 × 0.6 | **S = 1.5** |
| 9 | ЧИТАЮ | R3 предложение, верно | 6.19, t=7, R=0.889 | G = 4.5·5.8·0.761·0.117·0.9 = 2.10 | **S = 19.2** |

Как читать таблицу:

- ЧИТАЮ растёт быстро: 1.25 → 6.2 → 19 дней. Для движка это уже не проблема
  слова.
- ПИШУ и ПИНЬИНЬ **держит пара**. Пока 买/卖 не различаются стабильно,
  интервалы не расползаются, даже если отдельные ответы верны. Это и есть
  «повышать интервал только после успешного различения».
- Anki с одной карточкой «买 → покупать» к дню 9 показал бы интервал ~2
  недели и **ни разу не заметил бы**, что пользователь путает 买 с 卖 при
  воспроизведении.

## 5. Error-driven learning — классификация ошибок и реакции

### Классификатор (детерминированный, без ИИ)

```
classify(exercise, answer, target):
  если answer пуст / «не помню» / таймаут      → BLANK
  если answer == target                         → OK (+ скорость → Easy/Good/Hard)
  если answer — другая лексема словаря пользователя
     или её чтение/форма (пиньинь 卖, знак 卖)  → CONFUSION(partner)
  ПИНЬИНЬ: слог совпал, тон нет                  → TONE(ожидался, получен)
  ПИНЬИНЬ: слог не совпал                        → SYLLABLE
  ПИШУ: выбран знак с общим компонентом          → FORM_SIMILAR(partner)
  ПИШУ: выбран омофон                            → HOMOPHONE(partner)
  ИСПОЛЬЗУЮ: слово верно, порядок неверен        → ORDER
  ИСПОЛЬЗУЮ: выбрано другое слово                → CONFUSION / COLLOCATION
  иначе                                          → WRONG
```

Партнёр путаницы запоминается, **даже если его нет в словаре пользователя**
(выбранный дистрактор — тоже слово). Пара ориентирована: 买→卖 и 卖→买
считаются отдельно, но интервенция общая.

### Реакции на четыре случая из постановки

**1. Знает значение 买, но путает с 卖** (CONFUSION / FORM_SIMILAR,
≥ 2 раза за 30 дней):

1. **Контрастная карточка** (генерируется один раз на пару, кэшируется для
   всех пользователей):
   ```
   买 mǎi (3-й тон) — покупать        卖 mài (4-й тон) — продавать
   卖 = 十 + 买: продаёшь — отдаёшь «сверху»
   买东西 — покупать вещи            卖东西 — продавать вещи
   ```
   Отличия — только те, что реально различают: форма (十 сверху), тон
   (3 против 4), одна пара коллокаций. Без лишнего.
2. **4–6 заданий на различение, вперемешку**: W2 с обоими в вариантах,
   P1 «买 или 卖 → mǎi или mài?», C1 с обоими в вариантах, X-предложения, где
   правильный ответ то 买, то 卖. Важно: **не 4 раза подряд 买** — иначе
   тренируется «жми левый».
3. **Пара ставится в расписание** как объект (S0 × 0.4 — успех сразу после
   объяснения слабо доказателен).
4. **Ограничение интервалов обоих слов** — до S(пара) ≥ 7. Проверка пары
   дальше идёт уже внутри обычных упражнений (партнёр всегда в дистракторах).
5. Снятие: 3 успешных различения подряд на интервалах ≥ 1, ≥ 3, ≥ 7 дней
   → пара «решена». Её статус виден в прогрессе (раздел 9).

**2. Забывает пиньинь**:

- SYLLABLE → обычный провал ПИНЬИНЬ (k = 0.2), ЧИТАЮ не трогаем.
- TONE → k = 0.6 + счётчик тонов пользователя: если он систематически
  ставит 2 вместо 3 — это общая проблема, а не проблема слова. Тогда: тоновая
  разметка цветом (настройка) и P1 с вариантами, различающимися только тоном.
- Если у знака есть фонетик, и в словаре пользователя есть ≥ 2 слова с ним
  и одинаковым чтением (马/妈/吗 → ma) — подсказка «как в 妈 mā». Если
  фонетик врёт (а он часто врёт, см. раздел 6) — подсказку не показываем.
- Формат опускается на ступень (P2 → P1) до первого успеха, потом снова
  поднимается.

**3. Не может вспомнить знак** (ПИШУ, BLANK/WRONG):

- Показать разбор на компоненты с ролями (смысловой / звуковой), если данные
  есть — SHOULD; в MVP — хотя бы «знак 买 встречается в ваших словах:
  买东西, 买单».
- Формат вниз: W2 → W1 (с пиньинем), дистракторы проще. Через 2–3 задания в
  этой же сессии — повторная попытка.
- При leech (≥ 4 провала ПИШУ): предложить пользователю вариант «оставить
  слово только для чтения». Это честнее, чем мучить. Или попросить написать
  свою ассоциацию (самодельная мнемоника сильнее готовой) — SHOULD.

**4. Знает слово отдельно, но не может вставить в предложение**
(ИСПОЛЬЗУЮ проваливается при S(ЧИТАЮ) ≥ 7):

- Причина почти всегда — сочетаемость или конструкция, а не слово. Показать
  2–3 коллокации (买票, 买东西, 买了一个…) и одно предложение-образец.
- Формат вниз: C2 → C1, затем C2 с другим предложением (**новое
  предложение обязательно**: одно и то же выучивается как фраза).
- ORDER-ошибки (слово верно, порядок нет) копятся на уровне конструкции
  (想 + глагол, 在 + место + глагол). Когда их ≥ 3 у разных слов, это
  проблема грамматики, а не лексики — отдельная мини-интервенция по
  конструкции (LATER: грамматический трек).

**Общие правила:**

- ошибка никогда не наказывает навык, которого не касалась;
- на одной сессии — не больше 2 интервенций, остальные ждут завтра.
  Интервенция — дорогое внимание;
- **⚠ «Правильно со второй попытки» — не правильно**: k = 0.7, а не Good.
  Иначе вторые попытки превращаются в угадывание перебором.

## 6. Китайские механики — полезное и gimmicks

| Механика | Вердикт | Почему |
|---|---|---|
| **Слова с тем же знаком (морфемы, word families)** | **MUST (дёшево, сильно)** | Китайский строит слова из морфем: 电 → 电脑, 电话, 电影. «Знак 买 в ваших словах: 买东西, 买单» объясняет новое через известное, а данные уже есть (словарь пользователя + БКРС). Это главный китайский рычаг |
| **Похожие / путаемые знаки как дистракторы** | **MUST** | Без них W-упражнения тривиальны. Источник в MVP — ошибки пользователя, общие знаки, омофоны, кэш «путают с» от ИИ |
| **Пары путаницы из ошибок** | **MUST** | Раздел 5 — это ядро error-driven |
| **Компоненты с ролями (смысл/звук) как объяснение** | **SHOULD** | Помогает при провалах ПИШУ и путанице форм (卖 = 十 + 买). Нужны данные разбора: Make Me a Hanzi (`dictionary.txt`: разбор, радикал, этимология) или CJKVI-IDS + Unihan. **Лицензии проверить до использования** |
| **Фонетические компоненты для пиньиня** | **LATER, аккуратно** | Работает частично: фонетик даёт точное чтение с тоном заметно реже чем в половине случаев. Показывать только когда в словаре пользователя фонетик реально работает на ≥ 2 словах, иначе учит ложному правилу |
| **Пары-антонимы (买/卖, 借/还, 左/右)** | **Осторожно: не вводить вместе** | Исследования запоминания лексики: слова одного семантического поля и антонимы, **выученные одновременно**, мешают друг другу (интерференция). Антоним — только после того, как первое слово на «Узнаю». Как контраст при путанице — да |
| **Заучивание 214 ключей** | **Gimmick** | Список ключей ради списка не переносится на чтение. Ключ полезен внутри разбора конкретного знака, не отдельным курсом |
| **Сборка знака из компонентов** | **Gimmick / LATER** | Узнавание с подсказкой, см. раздел 3 |
| **Анимация порядка черт** | **Только внутри W3** | Если пользователь учится писать рукой — да, как проверка. Отдельно «посмотреть анимацию» — пассивное потребление, не recall |
| **Тоновые цвета** | **SHOULD, настройка** | Дешёво, многим помогает при TONE-ошибках, но не всем. По умолчанию выкл., предлагается при систематических тоновых ошибках |
| **Готовые мнемонические истории от ИИ** | **LATER** | Самодельная ассоциация работает лучше готовой; готовая — только как пример по кнопке при leech |

## 7. Context generation — ИИ-контекст

### Архитектура: генерировать глобально, фильтровать лично

Предложение для 买 на уровне HSK1–2 годится тысячам пользователей.
Генерировать его под каждого — дорого и медленно. Схема:

1. **Генерация** — один раз на `(headword, reading, смысл, уровень, тир)`,
   пачкой 8–12 предложений. Хранится глобально (`context_sentences`) с уже
   нарезанными словами.
2. **Проверка кодом** при генерации: нарезка по словарю (max-match по
   `dictionary_entries.headword` + `hsk_words`), целевое слово на месте,
   длина в пределах тира, в `ru` есть кириллица, пиньинь совпадает со
   словарём для целевого слова. Не прошло — в корзину.
3. **Подбор под пользователя** при построении сессии: брать предложение, где
   **все слова кроме целевого** известны пользователю (S(ЧИТАЮ) ≥ 3 или
   HSK ≤ его уровня минус 1, плюс служебные: 的/了/是/我/你/他/不/很/吗…).
   Нет подходящего — генерация «под заказ» с явным списком известных слов.
4. **Покрытие** — главная метрика: в T1–T2 неизвестных 0, в T3 — ≤ 1
   (с подсказкой по тапу). Это и есть i+1: понятно всё, кроме одного.

«Уровень пользователя» — не самооценка, а производная: доля HSK1, HSK2…
слов, которые у него на «Узнаю» и выше. Самооценка — только стартовое
значение.

### Тиры усложнения

| Тир | Что | Пример для 买 |
|---|---|---|
| T1 | коллокация, 2–4 знака | 买票 · 买东西 |
| T2 | простое предложение, одно известное недавнее слово пользователя | 我想买咖啡。 |
| T3 | предложение с конструкцией или 2 клаузы | 这个太贵了，我不买。 |
| T4 | реплика мини-диалога, контраст с партнёром путаницы | A: 这个多少钱？ B: 十块。 A: 便宜！我买两个。 |

### Структура промпта

```
SYSTEM
Ты пишешь короткие китайские фразы для ученика, чей родной язык — русский.
Цель — чтобы ученик вспомнил и употребил ОДНО слово в естественной фразе.

Правила:
1. Используй слово TARGET ровно в указанном смысле SENSE_RU. Если слово
   многозначно — только этот смысл.
2. Все остальные слова — ТОЛЬКО из KNOWN_WORDS и FUNCTION_WORDS. Если без
   чужого слова фраза не складывается — напиши другую фразу, а не добавляй
   слово.
3. Грамматика — только из GRAMMAR_ALLOWED.
4. Длина — LEN_MIN–LEN_MAX иероглифов.
5. Так говорят люди: в магазине, в чате, дома. Не «это книга», не «小明是
   学生», не лозунги, не перечисления. Разные подлежащие и ситуации в пачке.
   Никаких имён 小明/小红.
6. Если задана THEME — ситуация из этой темы.
7. Если задан CONTRAST_WITH — половина фраз с TARGET, половина с ним, так,
   чтобы по смыслу подходило только одно.
8. ru — естественный русский перевод, не подстрочник.
9. tokens — фраза, разрезанная на слова, как в словаре.
10. alt_orders — другие допустимые порядки слов (для сборки из плиток).

USER (JSON)
{ "target": "买", "reading": "mǎi", "sense_ru": "покупать",
  "tier": "T2", "len": [5, 10],
  "known_words": ["我","想","咖啡","水果","便宜","太","贵","超市","去", …≤150],
  "function_words": ["的","了","是","不","很","吗","在","这","那","个", …],
  "grammar_allowed": ["想+V","去+место+V","太…了","不+V","V+了"],
  "theme": "Покупки", "contrast_with": null, "count": 10 }

OUTPUT SCHEMA
{ "items": [ { "zh", "pinyin", "ru", "tokens": [..], "target_index",
               "alt_orders": [[..]], "tier" } ] }
```

Почему так:

- `known_words` ≤ 150 и **отбираются**, а не весь словарь: сначала слова той
  же папки (тема), потом недавние, потом самые устойчивые. Длинный список —
  дорого, а модель в нём тонет.
- **Код, а не модель, решает, прошла ли фраза.** Модель нарушает п. 2 регулярно
  — это известное поведение LLM при длинных ограничениях.
- **Естественность** держится на запрете шаблонов, требовании ситуации и
  разнообразии в пачке. Автоматическая оценка естественности — LATER
  (второй проход модели-рецензента, если жалобы будут).
- **⚠ Критика**: «ИИ генерирует контекст на лету при каждом упражнении» —
  плохая идея: задержка 2–5 секунд на задание, стоимость, нестабильное
  качество, невозможность проверить. Только кэш + фоновая догенерация.

## 8. Папка → обучение

### Что папка делает, а чего — нет

**⚠ Критика «урока по папке».**

- **Блочная практика.** 15 слов одной папки подряд — это блок, а
  перемешивание (interleaving) даёт лучшее долговременное удержание, хоть
  внутри сессии и кажется труднее.
- **Интерференция в семантических наборах.** Папка «Еда» (火锅, 豆腐, 葱,
  金针菇, 辣椒) — это слова одного семантического поля. Исследования
  (Tinkham, Waring, Erten & Tekin) показывают: такие слова, введённые
  одновременно, путаются чаще, чем несвязанные. А **тематическая** связка
  (сцена «идём на рынок»: 买, 便宜, 袋子, 辣椒) — помогает.
- Вывод: **вводить новые слова из папки порциями с перемешиванием, а
  связывать их потом — сценой**, когда они уже узнаются.

### Механика

1. **Ежедневная сессия «Сегодня»** — одна кнопка, общая для всех папок.
   Повторения — из всех папок перемешанно, новые — из очереди приёма. Никаких
   ручных запусков по папкам не нужно.
2. **Очередь приёма** — порядок, в котором новые слова идут в обучение:
   папка в фокусе → недавно добавленные папки (недавность = намерение) → по
   HSK. Из одной папки — не больше 3 новых в день, если есть другие. Слова
   одного узкого поля (5 видов овощей) разводятся по дням.
3. **Готовность папки**: доля слов на «Узнаю» и выше. Показывается на
   карточке папки.
4. **Сцена папки** (мини-миссия) — открывается, когда в папке ≥ 5 слов на
   «Вспоминаю» (и ≥ 60% слов на «Узнаю»). Сцена — это **не новое обучение, а
   извлечение в контексте**:
   - 1 ситуация на 4–6 реплик (T4), собранная только из известных слов;
   - 5–8 заданий: C1 → C2 → C3 → одна реплика C4 (перевод) → финальное
     чтение сцены целиком;
   - генерируется один раз на папку, пересобирается, когда в папке
     прибавилось ≥ 5 готовых слов.
   Сцена встраивается в «Сегодня» последним блоком (не чаще раза в неделю на
   папку) и доступна по кнопке на папке.
5. **Фокус** — пользователь ставит на папку «учить в первую очередь» (к
   поездке, к контрольной). Фокус влияет на приём и приоритет, не на
   блочность.
6. **Правило папки «только чтение»** — для папок-справочников (например,
   «Меню ресторана»): навык ПИШУ не открывается для её слов.

**⚠ Про «Matching» в сцене** — не нужно, см. раздел 3.

## 9. Прогресс без бессмысленной геймификации

**⚠ Критика «Выучено 347 слов»**: число добавленных или «пройденных» слов
растёт само и ничего не говорит о памяти. Опасно и обратное: проценты по
навыкам с точностью до единиц — ложная точность (раздел 2).

### Что показываем

1. **«Сейчас вы вспомните ~212 из 347 слов»** — сумма R по ЧИТАЮ. Это
   единственное число, которое честно отвечает «сколько я знаю сейчас». Оно
   может падать, и это нормально: падение — сигнал повторить, и рядом кнопка
   «Освежить».
2. **Воронка навыков** по всем словам:
   ```
   Узнаю        ████████████████████  298
   Вспоминаю    ███████████░░░░░░░░░  171
   Использую    █████░░░░░░░░░░░░░░░   74
   Устойчиво    ███░░░░░░░░░░░░░░░░░   41
   ```
   Прогресс — это движение слов вправо, а не рост первой строки.
3. **На карточке слова — 4 сегмента** (ЧИТАЮ · ПИНЬИНЬ · ПИШУ · ИСПОЛЬЗУЮ),
   у каждого 4 состояния: не начат / свежий / держится / устойчиво.
   По тапу — «когда повторим» и история ошибок («путали с 卖 — решено»).
4. **Решённые путаницы**: «Различаете: 买/卖, 已/己, 大/太». Это реальное
   достижение, которое пользователь чувствует.
5. **Недельный итог**: сколько слов перешло на следующую стадию, сколько
   пар путаницы решено, сколько слов «устойчиво» прибавилось.
6. **Прогноз нагрузки**: «Завтра ~35 заданий, ~8 минут». Снимает тревогу и
   объясняет, почему новых слов сегодня нет.

**Чего не делаем**: XP, уровни персонажа, лиги. Серию дней (streak) — только
мягко и с «заморозкой»: жёсткий streak заставляет делать бессмысленные
сессии ради цифры.

- Мнемоники от ИИ.
- Аудио: прослушивание, диктант, speaking — отдельный навык СЛЫШУ.

### Гипотеза и как её проверить

**Гипотеза:** многонавыковое расписание + работа с путаницей дают больше
слов, которые пользователь **воспроизводит** (ПИШУ/ИСПОЛЬЗУЮ) через 30 дней,
при той же нагрузке по времени, чем одна карточка «знак → значение».

**Метрики:**

- удержание воспроизведения на 30-й день (R2/W2/C2 на словах, не
  повторявшихся ≥ 14 дней);
- доля пар путаницы, решённых за 21 день;
- средние минуты в день и D7/D30 возврат пользователей;
- доля сессий, прерванных на середине (сигнал перегруза).

**Проверка:** A/B внутри продукта — половина новых слов пользователя идёт
по полной модели, половина — по режиму «только ЧИТАЮ». На день 30 — слепой
тест воспроизведения по обеим половинам.

## 11. UX flow: 买 mǎi — покупать

**Добавление.** Пользователь загрузил фото страницы учебника, из файла
пришли 买 и 卖 (уже работает). Слова сохранены в папку «Покупки». Создаются
лексемы, навыки закрыты, слова — в очереди приёма.

**День 0. Сегодня: 24 задания, ~6 минут, 4 новых слова.** Движок берёт 买,
но 卖 сегодня не берёт: пара известная, не вводим вместе.

*Знакомство (не оценивается):*

```
┌───────────────────────────────┐
│            买                  │
│           mǎi  ˇ 3-й тон       │
│        покупать                │
│                                │
│  我想买咖啡。                   │
│  Я хочу купить кофе.           │
│                                │
│  Знак 买 уже есть в ваших       │
│  словах: —                     │
│                    [Понятно]   │
└───────────────────────────────┘
```

*Через 3 других задания — первое вспоминание (R1):*

```
  买
  ○ продавать   ○ покупать   ○ дешёвый   ○ пакет
```

(Дистракторы — из папки «Покупки» и 卖, если он уже в словаре.) Верно.

*Ещё через 4 задания — P2:*

```
  买 — как читается?   [ mai3        ]   ✓ mǎi
```

**День 2. R2:**

```
  买          [Показать ответ]
  → покупать · mǎi       [Не вспомнил]  [Вспомнил]
```

Быстро «Вспомнил» → Easy. Открывается ПИШУ.

*W1:*

```
  покупать · mǎi
  买   卖   实   麦   头   马
```

Пользователь выбирает 卖. Мягкий разбор, без красного экрана:

```
  Это 卖 mài — «продавать».
  Нужен 买 mǎi — «покупать». Разница — 十 сверху.
                           [Дальше]
```

Путаница 买→卖 #1. В конце сессии W1 возвращается — верно (переобучение, в
расписание не идёт).

**День 3. P2:** вводит `mai4` → путаница #2 → **интервенция** (одна на
сессию):

```
┌──────── Разберём пару ────────┐
│  买 mǎi  ˇ   покупать          │
│  卖 mài  ˋ   продавать         │
│  卖 = 十 + 买                   │
│  «продаёшь — отдаёшь сверху»   │
│  买东西 · 卖东西                 │
│                [Потренируем]   │
└───────────────────────────────┘
```

4 задания вперемешку:

- 他在市场 ___ 水果。(Он на рынке продаёт фрукты.) → 卖;
- «покупать» → знак;
- 卖 → mǎi / mài;
- 我去超市 ___ 牛奶。→ 买.

4/4. Пара поставлена в расписание, интервалы 买 и 卖 ограничены.

**Дни 4–7.** Пара проверяется ещё дважды, внутри обычных заданий: 卖 всегда
среди дистракторов 买 и наоборот. День 7 — S(пара) ≈ 10, ограничение снято.

**День 8. Открыт ИСПОЛЬЗУЮ. C1:**

```
  我想 ___ 咖啡。  Я хочу купить кофе.
  买   卖   喝   去
```

**День 12. C2 (новое предложение, не то, что было при знакомстве):**

```
  «Это слишком дорого, я не куплю».
  [我] [不] [买] [太] [了] [贵] [这个]  →  这个太贵了，我不买。
```

**Неделя 3. Сцена «Покупки» открылась** (6 слов на «Вспоминаю»): диалог на
рынке из 买, 便宜, 袋子, 辣椒, 多少钱 + известных служебных, 6 заданий.

**Неделя 6–8. Устойчиво**: ЧИТАЮ ~60 дней, ПИНЬИНЬ ~35, ПИШУ ~30,
ИСПОЛЬЗУЮ пройден в 3 предложениях. Итого около 18–22 заданий на слово за 2
месяца, из них 6 — на пару с 卖 (они же учили и 卖).

На карточке слова:

```
  买 mǎi — покупать          Устойчиво
  Читаю ████  Пиньинь ████  Пишу ███░  Использую ███░
  Путали с 卖 — различаете с 30 сент.
  Следующее повторение: через 24 дня
```

## 12. Чем это лучше Anki + словарь + ChatGPT

Честно: **планировщик сам по себе — не преимущество.** В Anki есть FSRS, и
одну карточку он планирует не хуже нас. Преимущество — в том, что
планировщик знает то, чего Anki и ChatGPT знать не могут по устройству.

1. **Одна модель слова вместо набора несвязанных карточек.** В Anki
   «знак → значение», «значение → знак», «пиньинь» — три независимые
   карточки. Они не знают друг о друге: нет переноса успеха, нет
   разблокировки, нет ограничения интервалов из-за путаницы. Чтобы это
   собрать, нужно самому проектировать шаблоны — этого почти никто не делает.
2. **Оценку ставит система, а не человек.** В Anki пользователь сам жмёт
   «Good», и самооценка систематически завышена (особенно «ну почти
   вспомнил»). У нас большинство форматов проверяются автоматически, а ошибка
   классифицируется. «Почти» (тон, путаница) имеет своё число, а не «Again»
   или «Good».
3. **Путаница видна и лечится.** В Anki путаница 买/卖 невидима: человек
   нажал Again, и всё. У нас пары — объекты с расписанием, а решённые пары —
   видимый результат.
4. **Контекст из известных слов — с проверкой.** ChatGPT может написать
   предложение «для HSK2», но не знает, какие 347 слов пользователь
   **помнит сегодня**. У нас есть живая вероятностная модель лексикона
   (R по каждому слову), и код проверяет, что в предложении нет незнакомого.
   Это технически недостижимо для чат-бота без нашей базы — и это главный
   довод.
5. **Ноль ручной сборки.** Файл → слова → перевод → папка → упражнения без
   единой созданной вручную карточки. В Anki создание колоды — место, где
   бросает большинство.

**Где мы слабее** (не скрывать от себя):

- нет аудио — готовые Anki-колоды с озвучкой по аудированию сильнее;
- дисциплинированному пользователю Anki с продуманными шаблонами прирост
  меньше. Наша аудитория — те, кто колоду не соберёт никогда.

## Приложение A. Модель данных (набросок)

```sql
learning_lexemes      (id, user_id, headword, reading, sense_ru, dictionary_entry_id,
                       goal: 'full'|'read_only', created_at,
                       unique (user_id, headword, coalesce(reading,''), sense_key))
user_dictionary_items += lexeme_id              -- несколько папок → одна лексема
skill_states          (lexeme_id, skill: 'read'|'pinyin'|'write'|'use',
                       stability, difficulty, last_review, due, reps, lapses,
                       contexts_passed, unlocked_at, primary key (lexeme_id, skill))
confusion_pairs       (user_id, lexeme_a, lexeme_b | other_headword, count_ab, count_ba,
                       stability, difficulty, due, status: 'active'|'watch'|'resolved')
review_events         (id, user_id, lexeme_id, pair_id, skill, exercise_code,
                       prompt jsonb, options text[], answer text, outcome, error_type,
                       partner text, latency_ms, rating, r_before, s_before, s_after,
                       d_before, d_after, device, session_id, created_at)
context_sentences     (id, headword, reading, sense_key, tier, zh, pinyin, ru,
                       tokens text[], target_index, alt_orders jsonb, hsk_max,
                       source_model, validated_at)                       -- глобально
contrast_cards        (headword_a, headword_b, body jsonb)               -- глобально
learning_settings     (user_id, daily_budget, max_new, retention, tone_colors)
```

Расчёты FSRS — в клиенте (быстро, офлайн) и повторно на сервере при записи
события (сервер — источник истины, клиенту не доверяем).

## Приложение B. Открытые вопросы

   смысл = перевод, который сохранил пользователь; второй смысл = вторая
   лексема, только если пользователь добавил его явно.

4. Как считать «известно» для служебных слов, которые пользователь не

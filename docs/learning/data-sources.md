# Откуда берутся данные на экранах изучения слов

Статус: 2026-09-24 · к прототипу https://claude.ai/artifact/T723zN3h9cJnCeZ87ETFzC
и спецификациям `docs/design/specs/{today-session,exercise,folder-study,folder-map}.design.md`
(контракты — разделы §1).

Правило одно для всех экранов: **клиент ничего не считает**. Всё, что
касается памяти, стадий, сроков и правильности ответа, приходит с сервера
(TZ §3). Клиент только рисует и делит `count / total` для ширины полосок.

## Чего не хватает и куда это легло

1. **Чтение данных для экранов.** Сборщик сессии (#63) выдаёт задания, а сводки для экранов — «Сегодня», окно, карта папки, «Мой словарь» со стадиями, карточка слова — никто не отдаёт. → новая задача: Edge Function `learning-overview`.
2. **Порядок слов в папке** — колонка `user_dictionary_items.position`; при загрузке из файла — порядок файла, при ручном добавлении — в конец. Перенос старых строк — по `created_at`, внутри одной пачки порядок уже не восстановить. → в ту же задачу.
3. **Данные о знаках** (число черт — для стартовой сложности; разбор на компоненты — для «卖 = 十 + 买», дистракторов «похожий знак» и объяснений при ошибках «Пишу»). В базе их нет → #74.

   **Решение (2026-09-24): Make Me a Hanzi** (github.com/skishore/makemeahanzi).
   - `dictionary.txt` (LGPL-3): разбор IDS, ключ, этимология — какая часть смысловая, какая звуковая. Покрывает все 2663 знака слов HSK, полный разбор — у 2481 (93%); остальные — простые знаки (水, 心) или разбор с `？`.
   - `graphics.txt` (Arphic Public License): порядок черт → число черт; те же данные потом для рукописного квиза (`hanzi-writer` работает на них).
   - Условия: сырые файлы в репозиторий не кладём (скрипт скачивает при импорте), в приложении — строка об источнике.
   - Подсказка к паре строится **кодом из этимологии**, без ИИ: «卖 — смысловая часть 十, звуковая 买: читается похоже». Английские `hint` из набора не показываем.

   Пример: 卖 → `⿱十买`, звуковая часть 买; 买 → `⿱乛头`; 太 → `⿵大丶`.
4. **Примеры предложений** — только от ИИ с проверкой кодом (#64): в срезе БКРС их нет.
5. **Контрастные карточки** — `contrast_cards` (#71): по одной коллокации на слово пары от ИИ, проверка кодом (`_shared/learning/contrast.ts`), общий кэш; генерация в фоне при первой путанице. Строка разбора и подсказка — кодом из данных о знаках (#74).
6. **Подпись тона и озвучка для скринридера** — чистый код на сервере, вместе с #61/#63.
7. **Скорость пользователя** (минуты в плане, Easy/Hard) — медианы по `review_events`; пока данных нет, 4 задания в минуту и без Easy/Hard по скорости.

## Где считается

Всё, что зависит от времени (R падает каждый день), считается при чтении, а
не хранится: стадия, «пора освежить», «вспомните сейчас». Запись в базу —
только когда человек ответил (`review-submit`). Поэтому сводки отдаёт Edge
Function на Deno с той же моделью (`_shared/learning/`), а не SQL-представление:
иначе формулы жили бы в двух местах.

# `content/` — учебный материал до того, как он стал строками в базе

Здесь живут артефакты трёх контентных агентов. Полная архитектура —
`docs/CONTENT_AGENTS.md`; этот файл отвечает только на вопрос «что куда класть».

```
specs/<slug>.spec.json        learning-agent   — чему учим и как проверим (§5.2)
drafts/<slug>.content.json    content-agent    — сам материал (§5.3)
reviews/<slug>.review.md      content-qa-agent — вердикт, раунды дописываются снизу
approved/<slug>.content.json  content-qa-agent — побайтовая копия драфта на момент APPROVED
```

`<slug>` один на всю цепочку: `<тема>-<полоса>-<сценарий>-<номер>`, например
`clothing-a2-shopping-01`. По имени видно, какая спецификация породила какой
драфт и какое ревью.

## Как прогнать пакет

```bash
node scripts/content-validate.mjs <slug>      # gate B — до ревью, не после
node scripts/content-emit.mjs <slug> --batch <имя>   # только APPROVED, только из approved/
```

`content-emit.mjs` откажется работать, если: пакет не проходит gate B, вердикт
не `APPROVED`, или `approved/` отличается от `drafts/`. Последнее — не
придирка: одобренный пакет обязан быть тем самым драфтом, который читал
рецензент, иначе рецензент оказывается соавтором того, что подписал.

## Что здесь **не** лежит

SQL. Ни один агент его не пишет — `supabase/seed-*.sql` целиком генерируется
`content-emit.mjs` и правится только через исходный JSON. Первая партия
авторского контента загружалась четыре раза, потому что текст вида
«where you go **into a** building» доезжал до Postgres как синтаксис;
экранирование — механическая работа с одним правильным ответом, и она
вынесена в скрипт.
